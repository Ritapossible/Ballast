Reader against calendar

Does the model
ever change the answer?

A deterministic calendar rule can decide every night on its own. So the only question worth asking about the model is whether it ever reaches a different answer - and what happened when it did. On 6 of 96 nights the reader reached a different answer from the calendar, and Ballast did what the reader said. Those are the only nights on which the model can be said to have decided anything.

The derivation is checked, not asserted

The calendar's answer for a past night is re-derived by calling the same policy.decide the nightly run calls, with the model's judgment removed. On a night the reader abstained or failed a gate, the recorded decision is the calendar's - so every one of the 47 rule-decided rows is a test of that derivation. 46 of 47 reproduce exactly. The exception is ORCL on 2026-09-09, decided before the calendar rule checked the release time - the published defect, not a fault in this derivation.

The count is a floor

Nasdaq publishes a release-time flag for upcoming dates and drops it to not supplied for past ones, and an unsupplied flag passes both window gates. A re-derivation can therefore only ever flag more nights for the calendar than the live run saw, never fewer - which can only shrink the count of "calendar said no, model said hedge". Nights decided from now on carry the rule's own answer in the ledger entry beside the decision, so they need no re-derivation at all - 48 of the 144 rows on the chain do so far.

How to read this

  • The model's authority stops at the judgment. An override can only ever add or remove a bounded hedge against a position already held. Size, direction and price stay with the policy and the enforcer, so a model that flips every night still cannot place a bet.
  • An override is the only attributable row. Where the reader agreed with the calendar, the night's outcome says nothing about the model - the rule would have produced the same decision with no model at all. Value added is shown only on the rows where the two disagreed.
  • Rows marked "hedged a night early" sit on a session decided before the release-time fix. The model was shown the buggy calendar flag, so comparing its call against the corrected calendar compares two different questions. They stay in the table and out of the counts.
  • Nothing here is a Sharpe claim. A handful of overrides over a handful of nights measures whether the model is load-bearing, not whether it is profitable. The claims this project stands on are on the Evidence page, measured over years.
